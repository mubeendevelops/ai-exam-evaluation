# Migrated 2026-08-28 from EasyOCR (detection) + TrOCR (recognition) — that

# this repo at all, only in git history before 2026-08-28.
paddleocr>=3.0
paddlepaddle>=3.0

# Second engine in the multi-engine "fallback OCR" framework
# (core/ocr_fallback.py, core/ocr_engines/) — PaddleOCR is no longer the
# pipeline's only OCR option; every registered engine reads each label
# region and the best-confidence read wins per region (see
# core/ocr_fallback.py's module docstring). pytesseract is a thin wrapper
# that shells out to the `tesseract` binary, which is NOT a pip package —
# install it separately via your OS package manager, e.g.
# `sudo apt-get install -y tesseract-ocr` (Debian/Ubuntu) or
# `brew install tesseract` (macOS). Without the binary,
# core/ocr_engines/tesseract_engine.py raises a clear RuntimeError and
# core/ocr_fallback.py skips it, falling back to whichever other engines
# ARE available — not required for --stub-extraction / --stub.
pytesseract>=0.3

# OpenCV (cv2) is imported DIRECTLY by core/diagram_shapes.py and
# core/table_extractor.py, but is deliberately NOT pinned here. It already
# arrives transitively via paddleocr, and this venv currently resolves cv2 to
# opencv-python-headless while also having opencv-contrib-python installed —
# adding a pin for one distribution on top of that would make the double
# install worse, not better. Relevant finding from the table-extractor engine
# comparison (CLAUDE_CONTEXT.md §7B): the img2table library needs
# opencv-contrib-python specifically (cv2.ximgproc.niBlackThreshold) and
# fails outright against opencv-python-headless — so do not swap the OpenCV
# distribution without re-testing the diagram pipeline, which depends on it.
#
# core/diagram_extractor.py and core/ocr_engines/ import these directly
# (PIL.Image for the fetched scan / engine crops, numpy to feed PaddleOCR's
# detector/recognizer arrays) — both currently arrive transitively via
# paddleocr/sentence-transformers, but a direct import should have a direct
# pin rather than relying on another package's dependency graph to keep
# providing it.
Pillow>=10.0
numpy>=1.24

# PDF page rasterization for booklet ingestion (core/booklet_ingest.py, Task 5).
# Chosen over pdf2image deliberately: pdf2image is a thin wrapper that shells

# would add a second "install this outside the venv" setup step of exactly the
# kind core/ocr_engines/tesseract_engine.py already has to apologize for (see
# the pytesseract note above — the tesseract binary is the existing example of
# this cost). pypdfium2 bundles its own libpdfium and needs nothing installed
# outside the venv.
#
# Already present transitively (paddlex pulls it in for its own PDF input
# support), but core/booklet_ingest.py imports it DIRECTLY, and a direct
# import gets a direct pin rather than relying on another package's dependency
# graph to keep providing it — the same rationale stated for Pillow/numpy
# immediately above.
pypdfium2>=4.0
