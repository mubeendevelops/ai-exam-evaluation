# Acceptance — Tarn AI Evaluation (P22; admin portal: P30)

Date: 7 Oct 2026 (section 3: 29 Oct 2026). Parts: (1) the running app compared with the prototype `docs/project_idea.html`, screen by screen; (2) the requirement checklist R1–R7 and C8–C30 of requirements v0.7; (3) the admin portal compared with `newrequirements/admin_portal.html` and the status of the new requirements D159–D169 (P30). Measured error rates are in `docs/benchmarks/summary.md`.

How the comparison was made: the prototype served from `docs/` and the app (`make up`, `make seed`, signed in as a seeded DEMO_COM teacher) side by side in Chrome, same window width; every screen of the prototype was opened in both, then the DOM and layout of the app screens were checked at laptop and phone width.

The prototype is the look and the layout; where the build plan or a requirement forced a different shape, the difference is listed with its reason. **D51** (user, 2026-10-03) is the standing rule: the build plan's tab names and scope win, and prototype-only features are added when the user asks.

### What remains before a real college can use it

1. Teacher validation of the keys and rubrics (C8) and teacher-marked booklets: every threshold, weight and calibration is a placeholder until then (O29, O54, O60–O63).
2. A university answer booklet to test layout (C18).
3. A Google Cloud account to run `deploy/gcp/` (O102) and a decision on production compute (O100).
4. A UI to save and list blueprints (O20): the Schema Designer cannot yet store what it designs.
5. Batch scale (C30): direct-to-bucket uploads (O39, O98) and more than one booklet at a time.
